# Versioned editorial registrations, ownership and trusted governance

Status: **Proposed on feature/asos-editorial-domain-contracts; awaiting review.** Date: 2026-11-01.

ASOS remains the sole kernel. This additive proposal keeps Catalog OS profiles/policies and legacy `catalog-os` project references, while adding versioned specialist registration metadata, a `novel-owner` reference and a verified-fact governance port. No production migration or identity activation is included.

`SpecialistProfile` remains the three-profile Catalog UI model. Execution/case specialist identity additionally admits namespaced IDs, but unknown IDs/versions have no policy authority. `createSpecialistRegistry` accepts versioned domain/capability metadata and rejects duplicates. Only separately reviewed editorial/validator policies are evaluated; metadata registration alone never grants permission. Six editorial registrations support observe/propose/authorize/apply; the independent validator supports observe/validate and cannot authorize, apply or certify its own work. A future additional domain needs a reviewed policy, not a registry-only permission entry.

`ProjectReference` is a runtime-validated union. The legacy branch is preserved. The new `asos-owner.v1` branch separately identifies owning domain `brutal-edit`, novel/manuscript/immutable-version/content digest and author issuer/subject; externalProjectId is the novel ID within this owner domain, never a Music Vault ID. Unsupported/ambiguous shapes and cross-domain/scope mismatches are rejected. Novel case creation and authority evaluation bind the exact Case ID and execution context.

`TrustedGovernanceResolver` must independently verify session identity, owner-domain read/write scope, approval authenticity and current revocation. The kernel receives normalized facts: access receipt ID, actor, exact owner reference, allowed actions, expiry/revocation, optional author approval and independent validator context. Approval binds project, case, specialist/version, action/stage, approved scope/objective, exact proposal SHA-256 and execution ID. Human boolean fields are ignored for editorial authority; missing, expired, revoked, unknown or mismatched proofs fail closed. Successful decisions retain access/approval provenance. No AIBRY ID verifier, signing service or production resolver is supplied by this proposal.

The existing application service remains the orchestrator. It validates runtime input/output, resolves governance externally, records authority through the real kernel, refreshes before execution, uses original stable command identities, validates version-bound evidence and saves through the existing CAS port. Editorial Case binding is immutable and closed Cases cannot be reused for another stage/objective/digest. Replays require verified access; they do not reopen Case lifecycle. Owners retain original manuscript state in their domain; the kernel does not own it.

Execution evidence carries existing command metadata plus owner schema, novel/manuscript/version/hash, author and proposal digest. A distinct validator principal receives independently authorized access to the applied result; proposer/executor self-certification is prohibited. Deterministic tests use independently supplied verified-fact fixtures only, never local manuscript fixture grants as real ASOS decisions.

Coordination remains an idempotent-command protocol: if owner commit succeeds and Case save fails, repeat the original command, recover its durable owner receipt, return identical bound evidence and let the application service conditionally persist it. There is no distributed atomicity claim. Production activation requires accepted contracts, authenticated/verified receipts and owner transaction/revocation/outbox conformance together.

Regression test assertions are retained. Their old per-file transpilation loaders were replaced with native TypeScript loading under tsx because the real domain now imports runtime validators; new conformance tests also exercise the compiled exported package. The old detached data-URL loader could not resolve these dependencies. No compatibility assertions were removed to conceal failures.
